# FEATURE-ROUND55 — v1.9.6

یک ویژگی اسکوپ‌شده بر اساس درخواست کاربر (هیچ چیز دیگری دست نخورد، هیچ چیز حذف نشد).

## درخواست

هر بروکری که کاربر از طریق متاتریدر به آن وصل می‌شود، سرورهای مخصوص خودش را دارد. بخشی کوچک به اپ اضافه شود که:

1. لیست سرورهای بروکر را نشان دهد (با پینگ).
2. اپ به‌صورت پیش‌فرض به کم‌پینگ‌ترین سرور وصل باشد.
3. کاربر بتواند بین سرورها سوئیچ کند.
4. قابلیت رفرش/اسکن مجدد سرورها وجود داشته باشد.

دقیقاً مثل خود متاتریدر — کاربر اسکرین‌شات دیالوگ ورود ترمینال را فرستاد: ردیف «Network Rescan» با آیکون رفرش سبز، سپس سطرهای سرور (آیکون میله‌های سیگنال + نام + پینگ «101.94 ms» راست‌چین) با کادر انتخاب روی سطر فعال.

## اجرا

### UI — صفحهٔ ورود (`src/renderer/index.html` + `src/renderer/js/ui/login.js` + `src/renderer/css/app.css`)

بخش `#srv-scan` بین فیلدهای MT5 و حساب‌های ذخیره‌شده، برای هر دو حالت Demo و MT5:

- **دکمهٔ Network Rescan** (آیکون رفرش سبز SVG + برچسب — مثل عکس) → اسکن مجدد پینگ‌ها.
- **سطرهای سرور** (`.srv-row`): آیکون ۴ میلهٔ سیگنال (تعداد میلهٔ روشن بر اساس پینگ: ≤120ms→۴، ≤200→۳، ≤350→۲، بیشتر→۱؛ رنگ سبز/کهربایی/قرمز) + نام سرور + پینگ «xx.xx ms» با فونت tabular راست‌چین.
- **مرتب‌سازی صعودی** — سریع‌ترین بالا (مثل عکس ترمینال).
- **انتخاب پیش‌فرض = کم‌پینگ‌ترین** سطر (کادر انتخاب مثل ترمینال). ترتیب اولویت انتخاب: انتخاب دستی همین نشست ← انتخاب ذخیره‌شده ← سریع‌ترین سطر.
- **سوئیچ با کلیک**: در حالت MT5 نام سرور در فیلد «Server» پر می‌شود (مسیر اتصال قبلی بدون هیچ تغییری از همان فیلد استفاده می‌کند)؛ در حالت Demo انتخاب در `localStorage` (کلید `mt5_dc_demo`) ذخیره می‌شود — هویت اکانت/شناسهٔ ذخیره‌شده‌ها تغییری نمی‌کند.
- **ری‌اسکن** انتخاب دستی را حفظ می‌کند و فقط پینگ‌ها را تازه می‌کند؛ اگر انتخاب دیگر در لیست نباشد → auto-pick سریع‌ترین.
- اسکن با انتخاب هر کارت شروع می‌شود (یک بار per mode در هر بارِ صفحه)؛ هنگام اسکن «Scanning network…» نمایش داده می‌شود.

### منطق اسکن (`login.js` — `scanServers`/`renderServers`/`applyServerScan`)

- سوکت WebSocket **موقتی** به همان آدرس Feed (`ws://127.0.0.1:8777` — از CSP موجود) باز می‌کند: اول `{'type':'servers'}` برای لیست، بعد برای هر سرور `{'type':'servers_ping'}` — پاسخ‌ها با `req_id` جمع می‌شوند؛ تایم‌اوت ۹ ثانیه؛ سوکت بسته می‌شود.
- در اپ الکترون، قبل از اسکن `startProvider` با **همان هویتی که دکمهٔ Connect استفاده می‌کند** صدا زده می‌شود → پرووایدر در حال اجرا REUSE می‌شود (بدون اسپاون مجدد/ری‌استارت)؛ در وب/تست‌ها (بدون electronAPI) پرووایدر در حال اجرا فرض می‌شود.
- حالت MT5 بدون هویت (سرور و لاگین خالی) اسکن نمی‌کند (اسپاون بریج بی‌اعتبار نباید اتفاق بیفتد) — پیام راهنما نمایش داده می‌شود.
- گارد `srvToken`: اسکن جدیدتر، رندر اسکن قدیمی را بی‌اثر می‌کند.

### پرووایدر (`provider/provider_common.py` + `demo.py` + `mt5.py`)

- دو RPC جدید در دیسپچ مشترک (بدون نیاز به لاگین — مثل `ping`):
  - `servers` → خروجی `server_entries()` = `{'servers':[{name},...]}`.
  - `servers_ping` → `server_ping_ms(name)` = RTT اندازه‌گیری‌شده سمت پرووایدر از سوکت اسکن؛ `null` = غیرقابل اندازه‌گیری (سطر «—»).
- هوک‌های پایه روی کلاس `Broker` (لیست خالی / None) — زیرکلاس‌ها override می‌کنند:
  - **Demo**: شش دیتاسنتر با نام‌گذاری ترمینال (`UK01 AS`، `DE01 DC`، `DE02 DC`، `DE03 DC`، `FI01 DC`، `AE01 DC`) و پروفایل تأخیر per-server (±۸٪ jitter در هر اسکن) → پینگ‌های اندازه‌گیری‌شدهٔ کلاینت واقعاً متفاوت و معنادارند؛ auto-pick/data-driven است.
  - **MT5 bridge**: سرور واقعی اکانت (از فیلد Server یا `terminal_info().server`) + اندازه‌گیری REAL دور-رفت ترمینال (`terminal_info()` در executor). API اتوماسیون متاتریدر لیست دیتاسنترهای داخلی ترمینال را ارائه نمی‌دهد (آن اسکن داخل خود ترمینال است) — بنابراین لیست بریج، سرورهای واقعی شناخته‌شدهٔ اکانت را با پینگ واقعی می‌سنجد.

## رفتار پس از اجرا

- باز شدن صفحهٔ ورود → اسکن خودکار → لیست مرتب بر اساس پینگ → سریع‌ترین، پیش‌فرض اتصال.
- کلیک روی هر سطر = سوئیچ؛ رفرش = پینگ تازه؛ انتخاب دستی ماندگار.
- مسیر اتصال، هویت اکانت، تیک‌ها و همهٔ رفتارهای چارت دست‌نخورده — اسکن فقط خواندنی است.
