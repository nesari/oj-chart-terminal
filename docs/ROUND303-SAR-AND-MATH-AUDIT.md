# راند ۳۰۳ — SAR خوانا + آدیت عددی اندیکاتورها

> **خلاصه:** دو کار انجام شد.
> ۱) نقاط Parabolic SAR حالا خوانا هستند — علت هرگز اندازه نبود، **رنگ** بود.
> ۲) یک آدیت با زاویهٔ تازه ساخته شد که چهار هارنس قبلی نداشتند: «آیا **عدد**ی
>    که اندیکاتور چاپ می‌کند درست است؟» این آدیت **یک باگ واقعی** پیدا کرد:
>    تصادم شناسهٔ نمونه‌ها، که باعث می‌شد با افزودن سریع چند اندیکاتور یکی‌شان
>    بی‌صدا گم شود.

---

## ۱) SAR — علت، رنگ بود نه اندازه

گزارش R302 اندازهٔ نقاط را مشکوک کرده بود (`pointMarkersRadius: undefined`).

### اندازه‌گیری، فرضیه را رد کرد

LWC رادیوس را از `lineWidth/2 + 2` می‌سازد — با `linewidth = 2` یعنی **۳px**، که
از قبل اعمال می‌شد. A/B روی اسکرین‌شات واقعی (پیکسل اشباع‌شده در پنل قیمت):

| تنظیم | پیکسل رنگی | دلتا نسبت به «بدون SAR» |
|---|---|---|
| `radius = undefined` (پیش‌فرض) | ۱۸۶۳۶ | **+۵۱۸** |
| `radius = 3` | ۱۸۶۴۳ | +۵۲۵ |
| `radius = 5` | ۱۸۶۹۸ | +۵۸۰ |

بزرگ‌کردن رادیوس فقط **+۱۲٪** داد. پس مشکل اندازه نبود.

### علت واقعی

اسکریپت رنگ را از **روند** می‌گرفت:

```pine
color = sar < close ? #26a69a : #ef5350
```

این تقریباً **همان** سبز/قرمز کندل‌های اپ است (`#089981` / `#f23645`)، پس هر نقطهٔ
۳ پیکسلی روی یک شاخهٔ هم‌رنگ می‌نشست و محو می‌شد.

### رفع

TradingView خودش SAR را **یک پلات آبی** رسم می‌کند و روند را در رنگ نقطه کد نمی‌کند:

```pine
plot(sar, "Parabolic SAR", style = plot.style_circles, linewidth = 2, color = #2962ff)
```

آبی از **هر دو** رنگ کندل جدا می‌شود — همان خاصیتی که رنگ‌های قبلی نداشتند.

**اثبات:** با اسکریپت رفع‌شده، رنگ plot فقط `rgba(41,98,255,1)` است و پیکسل آبی
روی اسکرین‌شات **۵۹۷۹** است.

## ۲) آدیت جدید — و باگی که پیدا کرد

### چرا آدیت تازه لازم بود

چهار هارنس موجود (`audit_left_toolbar`، `audit_core_chart_tv`، `audit_app_sweep`،
`audit_app_deep`) همه یک سؤال می‌پرسند: «این سطح UI بدون خطا باز می‌شود؟»

R302 نشان داد این سؤال کافی نیست: ۱۴ اندیکاتور «حاضر، بدون خطا، دیالوگ سالم» بودند
و **هیچ‌چیز** رسم نمی‌کردند. Supertrend اجرا می‌شد، `status: ok` می‌داد و جهت را
هر کندل عوض می‌کرد. هیچ‌کدام برای گیت‌های موجود قابل دیدن نبودند.

آدیت R303 سؤال متفاوتی می‌پرسد: **«آیا عددی که اندیکاتور چاپ می‌کند با بازمحاسبهٔ
مستقل از کندل‌های خام می‌خواند؟»**

`tests/archive/e2e/audit_r303_indicator_math.py` — ۷۱ چک روی ۲۷ اندیکاتور، روی
فید زندهٔ دمو:

- **هویت‌های عددی:** `histogram == MACD - Signal`، `Volume == volume کندل`،
  `Momentum == close - close[n]`، `ROC == (close/close[n]-1)*100`،
  `OBV` هم‌جهت با close، `ATR > 0` و در مقیاس قیمت، `StdDev >= 0`،
  `RSI/MFI/Stoch/%R` داخل بازهٔ مجاز، نوارها با ترتیب `Upper >= Basis >= Lower`.
- **شکل سری:** «بلندترین run» برای Supertrend (باگ R302 دقیقاً run یک‌کندلی بود)،
  پوشش رنگ fill ابر ایچیموکو تا خانه‌های پیش‌بینی‌شده.
- **ناوردایی هویت:** `records == instances == sub-panes == DOM panes`، بدون id
  تکراری، و بعد از پاک‌کردن همه هیچ زیرپنل یتیمی نماند.

### باگی که پیدا شد: تصادم شناسهٔ نمونه

هر سه نقطهٔ ساخت شناسه از این عبارت استفاده می‌کردند:

```js
id: Date.now() + Math.floor(Math.random() * 999)
```

یعنی فقط **۹۹۹ فضای ممکن در یک میلی‌ثانیه**. افزودن ۱۵ اندیکاتور زیرپنلی «یک‌جا»
همهٔ ۱۵ قرعه را در یک سطل میلی‌ثانیه می‌گذارد. نرخ تولد برای ۱۵ قرعه روی ۹۹۹
فضا: **~۶٪ در هر دور**.

تصادم آرایشی نیست — هر دو رجیستری با همین id کلید می‌خورند:

| رجیستری | اثر تصادم |
|---|---|
| `pane._subs` (Map instId → زیرپنل) | `_ensureSub` دوم **روی اولی می‌نویسد** → دو اندیکاتور یک پنل، یکی هیچ‌جا رسم نمی‌شود → `subs=14` با ۱۵ رکورد |
| `rtMap` (Map instId → state) | rebuild دوم **جای state اول را می‌گیرد** → یکی اصلاً اجرا نمی‌شود → `insts=14` با ۱۵ رکورد |

**شاهد زنده از تریس آدیت:**

```
insts : [..., '1794918051634', ..., '1794918051634', ...]   <- تکراری
subs  : [..., '1794918059182', ...]  بدون هیچ نمونهٔ متناظر  <- یتیم
```

علامت کاربر: «گاهی یکی از اندیکاتورها موقع افزودن سریع (مثلاً بازیابی یک لی‌اوت
ذخیره‌شده) ظاهر نمی‌شود».

### رفع

`src/core/instance-id.js` — یک شمارندهٔ یکنوا با نگهبان per-pane:

```js
export function nextInstanceId(owner) { ... }
```

- idها **عدد** می‌مانند (پایداری، `data-*` و API عمومی همه عدد فرض می‌کنند).
- دو id ساخته‌شده برای یک پنل هرگز برابر نمی‌شوند.
- شمارنده اکیداً صعودی است، پس id بازنشسته دوباره صادر نمی‌شود.
- `dropInstanceIds(pane)` هنگام teardown.

هر سه سازنده (به‌علاوهٔ شناسهٔ رکورد قدیمی در `IndicatorsUI.add` که `pineMap` و
`data-iid` را کلید می‌زند) از همین عبور می‌کنند.

**اثبات:** با کد جدید ۵ اجرای متوالی آدیت سبز؛ با برگرداندن رفع، در ۲ از ۳ اجرا
باگ ظاهر شد (`dupRec=1`، `dupInst=1`).

## درسی که دو بار تکرار شد: «پیکسل روی canvas» معیار غلطی است

اولین نسخهٔ چکِ آدیت، پنل Awesome Oscillator را **خالی** گزارش کرد. واقعیت:
پلات `columns` از سری **بومی LWC** رسم می‌شود، نه canvas دست‌نقاشی پاین —
۹۹۱۱ پیکسل روی canvas خودِ زیرچارت داشت.

سپس نسخهٔ دوم، مجموع دو منبع را شمرد — که باگ R302 را **پنهان** کرد (canvas
زیرچارت همیشه شبکه و محور را می‌کشد و هرگز خالی نیست؛ با برگرداندن R302 سبز ماند).

نسخهٔ نهایی: برای هر پنل، **بیشینهٔ** جوهر دو منبع، با کف ۱۴۰۰ پیکسل (شبکه+محور
~۱۰۵۰ پیکسل است). هم اندیکاتور بومی را می‌بیند، هم پنل خالی را می‌گیرد.

## درسی که سه بار تکرار شد: بار در حال تشکیل، تست را فلیک می‌کند

چهار «یافتهٔ» اول آدیت (momentum، ROC، volume، HMA) و بعد OBV، همه از یک خطا
می‌آمدند: مقایسهٔ اسنپ‌شات موتور با **بازخوانی** کندل آخر، در حالی که کندل آخر
مدام تیک می‌خورد.

رفع: همهٔ مقایسه‌های عددی به **آخرین کندل بسته** (`N-2`) منتقل شدند.

دو مورد باقی‌مانده هم خطای خودِ آزمون بود، نه محصول:

| یافته | واقعیت |
|---|---|
| ROC «غلط» | اسکریپت `length = 9` دارد (پیش‌فرض TV)، آدیت `close[10]` می‌گرفت. حالا طول را از **سورس اسکریپت** می‌خواند. |
| HMA «بیرون باند» | `2*WMA(n/2) - WMA(n)` دو میانگین را **تفریق** می‌کند، پس مجاز است از باند بزند — همان چیزی که HMA را معروف کرده. آزمون اصلاح شد. |
| VWAP «بیرون باند» | VWAP از **ابتدای سشن** انباشته می‌شود، نه ۳۰ کندل. پنجره به روز معاملاتی تغییر کرد. |

بدون این اصلاح‌ها، آدیت روی یک سیستم سالم قرمز می‌شد — و گیتی که همیشه قرمز است
بدتر از نبودنش است.

### یک فلیک واقعی که در گیت پیدا شد

اولین اجرای کامل گیت، آدیت را قرمز کرد در حالی که تنها سبز بود. علت واقعی:

```
StochRSI %D = 100.00000000000024
```

اندیکاتورهای نوسانی در بازهٔ بسته تعریف می‌شوند (`[0,100]`)، اما روی `ta.sma`
ساخته شده‌اند که یک **جمع تجمعی O(1)** نگه می‌دارد
(`site.sum += v` و `evicted -> site.sum -= old`). روی ۵۰۰۰ کندل این انباشت
~۱ ulp رانش می‌کند: `100 + 2.4e-13`. TradingView هم با double حساب می‌کند و همان
مقدار گردشده را نشان می‌دهد، پس این عدد غلطی نیست که کاربر ببیند — ولی آزمون دقیق
`v <= 100` آن را به یک گیت فلیک ۱-از-۶ تبدیل کرد.

رفع: `RANGE_EPS = 1e-9` روی همهٔ بازه‌های بسته — **هفت مرتبه قدر** سخت‌گیرانه‌تر از
هر باگ فرمولی (خطای نسبت-به-تفاضل ~۱۰۰ برابر است) و بسیار ریزتر از دقت نمایش
۲ رقم اعشار، پس نمی‌تواند نقص واقعی را پنهان کند.

نتیجه: **۰ یافته در ۶ اجرای متوالی** و **۲۴/۲۴ گیت کامل در دو اجرای متوالی**.
