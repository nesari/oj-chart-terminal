# BUGFIX — راند ۴۴ (نسخه ۱.۸.۵): رنگ دارک‌مود مثل تریدینگ‌ویو

## گزارش کاربر

> «رنگ اپ ما توی حالت دارک تقریباً #131621 هست. برای تریدینگ‌ویو #0f0f0f هست. می‌خوام اپ ما هم رنگش توی حالت دارک مود مثل تریدینگ‌ویو بشه. فقط و فقط تمرکزت روی اصلاح این مورد باشه.»

اسکرین‌شات پیوست: سمت چپ تریدینگ‌ویو (بک‌گراند خنثیِ تقریباً مشکی `#0f0f0f`)، سمت راست اپ ما (بک‌گراند سرمه‌ای `#131722` — همان که کاربر ~`#131621` eyedrop گرفته بود).

## ریشه

تم تیرهٔ اپ از نسخهٔ **قدیمی** پالت دارک تریدینگ‌ویو کپی شده بود: پایهٔ سرمه‌ای `#131722` با گرادیان چارت `#131722→#0c0e15`. تریدینگ‌ویو بعداً پایهٔ دارک را به خنثیِ `#0f0f0f` تغییر داد. رنگ سرمه‌ای در ۵ لایهٔ اپ زنده بود:

| لایه | فایل | مقدار قدیمی |
|---|---|---|
| بک‌گراند DOM (body و پشت همه‌چیز) | `app.css` → `--bg` | `#131722` |
| بوم چارت (پیش‌فرض کارخانه) | `settings.js` → `bg1/bg2` | `#131722` / `#0c0e15` |
| بوم چارت (پیش‌فرض تم + مهاجرت تم) | `theme.js` → `CHART_DEFAULTS.dark` | `#131722` / `#0c0e15` |
| بوم چارت (fallback اسنپ‌شات) | `manager.js` → `getSnapshotPalette` | `#131722` / `#0c0e15` |
| صفحهٔ ورود + دو سطح نیمه‌شفاف | `app.css` (لاگین ×۲، `.pane-loading`، `.st-nav`) | `#1c2233→#131722`، `rgba(19,23,34,…) |

## تغییرات — فقط همین ۴ فایل

### ۱. `src/renderer/css/app.css`
- `--bg: #131722` → `--bg: #0f0f0f`
- گرادیان `#login-screen`: `#1c2233 0%, #131722 60%` → `#1e222d 0%, #0f0f0f 60%`
- گرادیان `.login-brand-col`: `#1c2233 0%, #131722 78%` → `#1e222d 0%, #0f0f0f 78%`
- `.pane-loading` (پردهٔ Loading data): `rgba(19,23,34,.42)` → `rgba(15,15,15,.42)`
- `.st-nav` (ستون ناوبری تنظیمات): `rgba(19,23,34,.4)` → `rgba(15,15,15,.4)`

### ۲. `src/renderer/js/core/theme.js`
- `CHART_DEFAULTS.dark`: `bg1 '#131722'→'#0f0f0f'`، `bg2 '#0c0e15'→'#0a0a0a'`
- **مهاجرت legacy (نکتهٔ کلیدی)**: ثابت جدید `LEGACY_DARK_DEFAULTS = { bg1:'#131722', bg2:'#0c0e15' }` و گسترش شرط مهاجرت در `Theme.apply()`. چرا لازم بود؟ مکانیزم قبلی فقط وقتی مقدار فعلی = پیش‌فرض تم *مخالف* باشد مهاجرت می‌کرد؛ کاربران فعلی `#131722` را به‌صورت مقدار ذخیره‌شده در localStorage دارند و بدون این شرط، رنگ سرمه‌ای روی دستگاه خودشان باقی می‌ماند. قانون حفظ انتخاب کاربر دست‌نخورده ماند: مقداری که نه legacy باشد نه پیش‌فرض factory هیچ‌کدام از دو تم = انتخاب عمدی کاربر و هرگز تغییر نمی‌کند.

### ۳. `src/renderer/js/chart/settings.js`
- `DEFAULTS`: `bg1 '#131722'→'#0f0f0f'`، `bg2 '#0c0e15'→'#0a0a0a'`

### ۴. `src/renderer/js/chart/manager.js`
- `getSnapshotPalette` fallback دارک: `bg1/bg2` → `#0f0f0f/#0a0a0a`

## عمداً تغییر نکرد (خارج از درخواست)

- خانوادهٔ پنل/بوردر/هاور: `--panel #1e222d`، `--panel2/--border #2a2e39`، `--border2 #363a45`، `--pane-sep #414653` — این‌ها همان خاکستری‌های کلاسیک تریدینگ‌ویو هستند که در پالت جدید هم برای سطوح بالاتر استفاده می‌شوند؛ سلسله‌مراتب خوانایی حفظ شد.
- همهٔ رنگ‌های متن (`#d1d4dc/#787b86`)، گرید `rgba(42,46,57,.55)`، کراس، واترمارک، مقیاس‌ها.
- چیپ‌های شیشه‌ای روی بوم (`rgba(24,28,39,…)` در `theme.js/tools.js/tools2.js`) — کروم شناورند نه بک‌گراند.
- پالت انتخاب رنگ در `toolbar.js` (سواچ `#131722` یکی از ۸ سواچ پالت است، نه سطح UI).
- تیکِ داخل آیکون checkbox (`icons.js` `checkOn`).
- **تم روشن به‌طور کامل** (`--text/--white/#131722` روشن، `bg1 #ffffff`، …).
- هیچ رفتار، چیدمان، منطق یا فایل دیگری.
