# BUGFIX — راند ۷۷ (v1.9.28): «تنظیمات باز می‌شود ولی هیچ‌چیز روی چارت رسم نمی‌شود»

## گزارش کاربر

> «عالیه. الان پنل تنظیمات لود شد. اما یک مشکلی وجود داره. هیچ چیزی روی چارت رسم نمیشه. اندیکاتور من یک سری باکس ها و نوشته ها رسم میکنه روی چارت. الان بخش تنظیمات پنل درسته. ولی چیزی روی چارت رسم نمیشه همچنان.»

یعنی راند ۷۶ (دیالوگ تنظیمات) درست شده، اما خروجی گرافیکی خود اندیکاتور ۷۸۶ Zones (باکس‌های سشن + لیبل‌ها + خطوط میانی) روی چارت ظاهر نمی‌شود. درخواست: ریشه‌یابی و رفع.

## چرا این باگ در تست‌های راند ۷۴ دیده نشد؟

`verify_pine74.mjs` چک «ثبات تعداد اشیاء روی تیک» را فقط با **یک** `updateForming` انجام می‌داد و `runChunked` را بدون تیک موازی اجرا می‌کرد — هر دو باگ زیر فقط با «اجرای کاملِ chunked + جریان زندهٔ تیک + چندین rollback پشت‌سرهم» فعال می‌شوند؛ یعنی دقیقاً شرایط چارت واقعی.

## ریشه‌یابی (با پروب زندهٔ رویداد، `probe_race.py`)

پروب، `store.add` / `store.del` / `updateForming` / `runChunked` را wrap کرد و تایم‌لاین دقیق را گرفت. وضعیت آلوده: `adds: {box: 9, label: 9}` ولی `boxes: 0, labels: 0` — یعنی اشیاء **ساخته** شده‌اند و بعد **حذف** شده‌اند و هرگز بازسازی نشده‌اند. سه ریشه:

### BUG-76-A — aliasing مصنوعِ snapshot/rollback (ریشهٔ اصلی «محو شدن» اشیاء)

`snapshot()` آرایه‌های Pine را با `snapshotClone()` کلون می‌کرد، اما `restore()` **همان شیءِ کلون‌شده را با ارجاع به state زنده می‌داد**. اسکریپت ۷۸۶ Zones مرجع باکس‌ها را در آرایه‌های `var box[]` نگه می‌دارد؛ اولین `array.set()` در بارِ در حال شکل‌گیری، **خودِ اسنپ‌شات** را آلوده می‌کرد. rollback بعدی مرجع‌های اشیائی را برمی‌گرداند که `dropObjectsBornAfter` قبلاً از استور حذف کرده بود → شرط `na(existingBox)` هرگز برقرار نمی‌شد → اسکریپت تا ابد شاخهٔ `box.set_*` را روی **شیء مرده** اجرا می‌کرد → استور برای همیشه خالی → هیچ‌چیز روی چارت رسم نمی‌شد. همان مشکل برای `sites` (شبیه‌سازی state سایت‌ها) هم بود.

**رفع** (`core/pine/interpreter.js` — `restore()`): معناشناسی copy-out — `cur.value = this._cloneVal(rec.value)` و `this.sites.set(key, cloneSite(s))`؛ هویت اشیاء رسم داخل آرایه‌ها طبق قرارداد رسمی Pine پایدار می‌ماند (فقط محتوا کپی می‌شود). `SeriesBuf` از قبل کپی-دوطرفته بود و دست نخورد.

### BUG-76-B — ورود تیک‌هوک به runtime در میانهٔ پاس chunked

تیک‌هوک (هر ۲۵۰ms) با دیدن `st.rt` بلافاصله `updateForming()` (و در شکاف چندباره‌ای `runAll()`) صدا می‌زد — حتی وقتی پاس کاملِ تاریخچه هنوز در حال yield به event loop بود. نتیجه: اجرای بار آخر با state نیمه‌ساخت (زون‌های نیمه‌انباشته) و آلوده‌شدن `_preFormSnap` قبل از پاسِ واقعی.

**رفع** (`chart/pine-ui.js`): فلگ `st.running` تمام طول `runFull` (fetch اینتربار + `runChunked` + sync) بالا می‌ماند؛ `onTickPane` چنین runtimeای را skip می‌کند؛ `runFull`های هم‌زمان به‌جای تداخل، یک‌بار re-queue می‌شوند (`pendingRerun`).

### BUG-76-C — `runAll` همگام در مسیر تیک (فریز/کرش روی تاریخچهٔ عمیق)

شکاف چندباره‌ای (مثلاً رسیدن صفحات قدیمی‌تر) یک `runAll()` **کامل و همگام روی thread اصلی** اجرا می‌کرد — برای اسکریپت سنگین روی تاریخچهٔ عمیق، ده‌ها ثانیه فریز و در بدترین حالت زنجیرهٔ run-after-run تا کرش تب.

**رفع**: مسیر از `runFull()` chunked عبور می‌کند (همان پاس کامل صادقانه، با yield هر ۴۰۰ بار و گارد BUG-76-B).

### BUG-76-D — اوورراید ورودی‌ها از بار ۱ به بعد بی‌اثر بود (کشف در همین راند)

هنگام تست «Days Back=3»، runtime هنوز `daysBack=1` می‌دید در حالی که `inputValues` مقدار درست را با id درست (`ig:140_1 → 3`) داشت. ریشه: id ورودی = `'i' + siteKey + '_' + n` که `n` شمارندهٔ site بود و **هر بار یک واحد رشد می‌کرد** — از بار ۱ به بعد id دیگر با id ثبت‌شده در `inputDefs`/دیالوگ (id بار ۰) یکی نبود → همهٔ اووررایدها خاموش به پیش‌فرض برمی‌گشتند. (تست راند ۷۴ این را نمی‌دید چون فقط «بدون خطا بودن» بازاجرا را چک می‌کرد، نه اثر مقدار.)

**رفع**: ریست `s.n` برای همهٔ sites در ابتدای هر `runBar` — `n` فقط برای شماره‌گذاری id ورودی استفاده می‌شود، پس ریست per-bar امن است و id در همهٔ بارها پایدار می‌شود.

## نتیجهٔ رفتاری

- باکس/لیبل/خط‌های ۷۸۶ Zones بعد از هر تیک طبق قرارداد رسمی Pine حذف و بازسازی می‌شوند (churn id طبیعی است) و تعدادشان روی چارت **پایدار** می‌ماند: ۶ سشن × daysBack روز.
- ویرایش هر ورودی در پنل تنظیمات (مثل Days Back) واقعاً به موتور می‌رسد: daysBack=3 → ۱۸ باکس (اثبات پروب + e2e).
- فریز/کرش مسیر «تاریخچهٔ عمیق + تیک» بسته شد.
