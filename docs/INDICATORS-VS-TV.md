# اندیکاتورهای داخلی — همه Pine، یک موتور (راند ۲۹۹)

> **تصمیم راند ۲۹۹:** هر ۲۷ اندیکاتور داخلی از جاوااسکریپت دست‌نویس به
> **اسکریپت Pine واقعی** تبدیل شدند. پیاده‌سازی JS قدیمی (`src/core/indicators.js`
> با `compute: (bars, p, c) => ...`) **حذف شد**. حالا فقط یک پیاده‌سازی از هر
> فرمول در برنامه هست: همان موتوری که اسکریپت‌های خود کاربر و نمونه‌های
> TradingView را اجرا می‌کند.

## چرا

آدیت دیفرانسیال راند ۲۹۸ نشان داد دو پیاده‌سازی موازی (JS بومی + موتور Pine) ذاتاً
اشتباه است:

- وجودش فقط برای **مقایسه با** موتور بود، نه برای کاری که موتور نمی‌کند؛
- چهار باگ **فقط** در نسخهٔ تکراری زندگی می‌کردند (Momentum نسبت به‌جای اختلاف،
  A/D بدون کندل صفر، SAR بدون clamp، StochRSI با ۵۰ جعلی)؛
- هر تغییر در یک طرف، طرف دیگر را بی‌صدا از TV دور می‌کرد.

## نتیجهٔ حذف

| قبل | بعد |
|---|---|
| `src/core/indicators.js` ≈ ۵۲۰ خط ریاضی JS | ۱۲۶ خط فاساد سازگاری (فقط نگاشت) |
| `indicators-ui.js` ≈ ۸۳۹ خط رسم LWC (سری، باند، رنگ) | آداپتور نازک روی PineUI |
| باند کانال‌ها با series primitive دست‌نویس | `fill()` استاندارد Pine |
| دو سیستم ورودی (params قدیمی + `input.*`) | یک سیستم: `input.*` |
| دو سیستم رنگ هیستوگرام | رنگ از خود اسکریپت (`plot(..., color=...)`) |

کل دیف: **−۱۱۸۳ خط خالص**، با ۲۷ اسکریپت جدید در `src/core/pine/builtins-catalog.js`.

## معماری جدید

```
کاربر → دیالوگ Indicators
          ↓
   IndicatorsUI.add(pane, 'rsi')
          ↓  (رکورد قدیمی روی pane.indicators برای سازگاری API)
   syncPine → PineUI.add(pane, 'builtin:rsi')
          ↓
   موتور Pine (همان موتور اسکریپت‌های کاربر)
          ↓
   PineRenderAdapter → چارت
```

- **`pane.indicators`** همان شکل قدیمی را نگه می‌دارد (`{id, type, params, visible}`)،
  پس API عمومی `window.__app.IndicatorsUI` و لی‌اوت‌های ذخیره‌شدهٔ کاربران
  می‌شکنند نه.
- **`pane.pineScripts`** نمونهٔ واقعی موتور است (`{id, scriptId, inputs, visible}`).
- `syncPine` این دو را هم‌گام می‌کند: ساخت، حذف، و انتقال پارامترها.
- اسکریپت‌های داخلی با پیشوند `builtin:` شناسایی می‌شوند: هرگز در «My Scripts»
  نمی‌آیند، قابل ویرایش/حذف نیستند و در حافظهٔ کاربر ذخیره نمی‌شوند.

## نگاشت پارامترها (سازگاری با لی‌اوت قدیمی)

هر تعریف یک نقشهٔ `params` دارد (کلید قدیمی → عنوان ورودی Pine):

```js
{ type: 'bollinger', params: { length: 'Length', mult: 'StdDev' } }
```

پس یک لی‌اوت ذخیره‌شده با `{ length: 50 }` پس از ارتقا روی ورودی درست می‌نشیند.

## تطابق با TradingView

هر اسکریپت با **پیش‌فرض‌های TV** نوشته شد و در `test_round298_299_indicator_parity`
(۵۷ چک) با مرجع مستقل سنجیده می‌شود، نه با خودش:

| اندیکاتور | نکتهٔ تطابق |
|---|---|
| Momentum | اختلاف قیمت (`ta.mom`)، نه نسبت |
| A/D | کندل اول هم شمرده می‌شود (`ta.accdist`) |
| SAR | کسرهای شتاب TV (0.02/0.02/0.2) به‌جای درصد |
| SuperTrend | تقسیم به دو سری up/down با `dir` مستند |
| Keltner | پایه EMA (TV)، نه SMA |
| Ichimoku | هر دو span با `offset = displacement` |
| MACD | هیستوگرام بر اساس **علامت** نسبت به صفر |
| Volume | رنگ بر اساس **جهت کندل** (close vs open) |
| Awesome | رنگ بر اساس **کندل قبل** |
| Stochastic/StochRSI/%R | دامنهٔ صفر → `na` (نه ۵۰/−۵۰) |

باندها با `fill(pU, pL, color.new(..., 9x))` پر می‌شوند — همان چیزی که TV می‌کند و
نسخهٔ JS هرگز رسم نمی‌کرد.

## تنظیمات

دیالوگ تنظیمات **همان** دیالوگ Pine است (بدون تکرار): سه تب Inputs / Style /
Visibility، رندر ورودی‌ها از `input.*`، انتخابگر رنگ کامل با آلفا، منوی
plot-style برای هر سری، و Ok که مستقیم روی نمونهٔ موتور می‌نشیند. سپس
`onCommit` مقادیر را به رکورد قدیمی برمی‌گرداند تا عنوان legend و ماندگاری
هم‌گام بمانند.

## باگ موتور که در این راند پیدا و رفع شد

`input.int` مقدار کسری را دست‌نخورده برمی‌گرداند، پس یک `20.5` ذخیره‌شده به
`ta.sma(close, 20.5)` می‌رسید و پنجرهٔ کسری `bars[19.5]` می‌خواند (اندیکاتور
بی‌صدا خالی). حالا `input.int` در همان نقطهٔ واحد، گرد و به minval/maxval
محدود می‌شود — رفتار TV.

## باقی‌مانده

- **Ichimoku** پایهٔ خطوط را با `offset` رسم می‌کند ولی «cloud fill بین دو span»
  در لبهٔ راست چارت تا آخرین کندل ادامه می‌یابد (TV فضای آینده را هم پر می‌کند).
  تفاوت بصری فقط در ناحیهٔ آینده است.
- اسکریپت‌های داخلی برای کاربر قابل ویرایش نیستند (عمدی: کاتالوگ برنامه هستند).
