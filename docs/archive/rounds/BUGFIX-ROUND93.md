# BUGFIX-ROUND93 — هایلایت (کراس‌هیر) موس، زمانِ اشتباه روی نوار زمانِ Custom Session

## گزارش کاربر

> «نوار زمان درست هست ولی هایلایت موس روی نوار زمان داره یه زمان دیگه ای رو
> نمایش میده»

یعنی: خودِ برچسب‌های ثابتِ نوار زمان (زیر هر ناحیه‌ی روز) درست بودن — مشکل فقط
در باکس شناور (pill) کراس‌هیر بود که هنگام حرکت موس روی چارت/نوار زمان، زمانِ
اشتباهی نشون می‌داد.

## ریشه‌ی باگ

نوار زمان ثابت (`_updateTaxExt` → `_xOf`) از قبل (راند ۹۰) از آرایه‌ی
GAP-INCLUSIVE (`pane._sessWithGapTimes`, از طریق `_timeArr()`) می‌خونه، چون
اندیس منطقیِ خودِ چارت (lightweight-charts) شکاف‌های سفیدِ بین نواحی روزانه رو
هم می‌شمره.

اما `_updateCrossBubble` (باکس شناورِ کراس‌هیر) توی شاخه‌ی غیر-sync (موقعی که
کاربر مستقیم روی همین چارت هاور می‌کنه، نه sync‌شده از چارت دیگه) هنوز از
`pane.barTimes` — آرایه‌ی فشرده و بدون شکاف — برای تبدیل اندیس منطقیِ زیر موس
به زمان استفاده می‌کرد:

```js
t = U.logicalToTime(pane.barTimes, l); // اشتباه: l شکاف‌ها رو می‌شمره، barTimes نه
```

نتیجه: بعد از اولین مرزِ روز (اولین gap)، هر بار که موس روی نواحی بعدی می‌رفت،
زمانِ نمایش داده‌شده به اندازه‌ی `GAP_BARS` (و تجمعی برای هر مرز روزِ بعدی) کج
می‌شد — دقیقاً همون باگی که راند ۸۷ برای `_xOf`/رسم‌های Pine حل کرده بود، ولی
همین یک نقطه (کراس‌هیرِ غیر-sync) از قلم افتاده بود.

## راه‌حل

`_updateCrossBubble` هم مثل بقیه‌ی مسیرها از `this._timeArr()` (همون آرایه‌ی
GAP-INCLUSIVE که `_xOf`/`_tOf`/نوار زمان استفاده می‌کنن) می‌خونه، نه
`pane.barTimes` مستقیم.

## محدوده‌ی تغییر

تنها فایلِ تغییریافته: `src/renderer/js/drawing/engine.js` — فقط دو خط داخل
`_updateCrossBubble` (منبعِ آرایه‌ی زمان). هیچ فایل دیگری تغییر نکرده؛ منطقِ
نوار زمانِ ثابت (`_updateTaxExt`, راند ۹۰/۹۱) دست‌نخورده باقی مونده چون طبق
گزارش کاربر از قبل درست بود.
