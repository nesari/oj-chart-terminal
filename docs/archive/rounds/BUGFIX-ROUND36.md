محدوده: فقط همین دو مورد؛ هیچ بخش دیگری تغییر نکرد.

## ریشهٔ باگ شماره ۱ (اثبات‌شده با بازتولید)

راند ۳۵ برای جستجوی بی‌حساس به حروف، کش نمادهای `mt5.py` را با اسلات جدید `'all'` گسترش داد:

```python
SYM_CACHE = {'names': [], 'all': [], 'at': 0.0}   # راند ۳۵
```

اما تابع قدیمی `_visible_symbols()` (که از راندهای قبل دست‌نخورده مانده بود) همچنان **کل دیکشنری را** جایگزین می‌کرد:

```python
SYM_CACHE = {'names': out, 'at': now}             # کلید 'all' حذف می‌شود!
```

زنجیرهٔ فراخوانی در ترمینال واقعی MT5:

```
هر تیک  →  next_tick()  →  server_now()  ──(هر ۳۰ ثانیه)──►  _newest_forming_m1()
                                                             →  _visible_symbols(4)
                                                             →  SYM_CACHE بدون کلید 'all'
```

پس چند ثانیه بعد از اولین تیک زنده، **هر** فراخوانی `search()` با `KeyError: 'all'` منفجر می‌شد. هندلر `symbol_search` در `provider_common.py` هر Exception را می‌بلعید و **هیچ پاسخی** برای کلاینت نمی‌فرستاد؛ فرانت‌اند ۲۰ ثانیه منتظر می‌ماند، timeout را در `catch (() => {})` گم می‌کرد و رابط کاربری «همیشه خالی» می‌ماند — در پنجرهٔ Symbol Search، سرچ Watchlist و سرچ Compare. (روی دمو بی‌اثر بود چون `demo.py` از این کش استفاده نمی‌کند؛ برای همین تست‌های راند ۳۵ سبز شده بودند و باگ فقط روی MT5 واقعی دیده می‌شد.)

اثبات بازتولید: `scripts/repro36_search_keyerror.py` — با ماژول تقلبی MetaTrader5 و شبیه‌سازی همان جریان (بوت → جستجوی اول OK → تیک → به‌روزرسانی آفست ۳۰ ثانیه‌ای → جستجو):

```
روی کد راند ۳۵:  FAIL  KeyError: 'all'
روی کد راند ۳۶:  PASS  3/3
```

## اصلاحات

### 1) `provider/mt5.py` — کش به سه اسلات مستقل شکسته شد

```python
SYM_CACHE = {'names': [], 'names_at': 0.0, 'all': [], 'all_at': 0.0, 'vis': set()}
```

- `_visible_symbols()` فقط اسلات خودش را می‌نویسد (`names` / `names_at`)؛ دیگر هیچ تابعی کل دیکشنری را بازنویسی نمی‌کند.
- `search()` اسلات `all` را با تایم‌استمپ مستقل (`all_at`، کش ۳۰ دقیقه‌ای) نگه می‌دارد.
- مجموعهٔ نمادهای visible (`vis`) در **همان یک** `symbols_get()` پر می‌شود — مرتب‌سازی «اول نمادهای visible» دیگر به‌ازای هر کلید تایپ‌شده یک `symbols_get()` کامل صدا نمی‌زند (روی بروکرهای سنگین یک بهینه‌سازی محسوس).
- لیست کامل تطبیق‌ها برگردانده می‌شود (بدون سقف ۸۰ قبلی) تا پاورقی «N symbols» عدد واقعی بروکر را نشان دهد.

### 2) `provider/provider_common.py` — هندلر `symbol_search` همیشه پاسخ می‌دهد

- حتی اگر هوک جستجو Exception بدهد، پاسخ با لیست خالی برمی‌گردد (دیگر هیچ خطایی نمی‌تواند UI را ۲۰ ثانیه معطل نگه دارد).
- پاسخ `total` (تعداد دقیق کل تطبیق‌ها) را حمل می‌کند؛ `symbols` روی سیم به ۴۰۰ نام محدود است.

### 3) فرانت‌اند — دسته‌بندی + شمارندهٔ پاورقی در Symbol Search

- `src/core/feed.js`: `Feed.search` حالا `{symbols, total}` برمی‌گرداند؛ سه محل مصرف به‌روز شدند (`toolbar.js`, `panels/watchlist.js`, `chart/compare.js`).
- `src/renderer/js/chart/toolbar.js`: نتایج پنجرهٔ نماد TV-سنچری گروه‌بندی می‌شوند —
  `Forex / Metals / Energies / Indices / Crypto / Stocks & Others` (فقط گروه‌های غیرخالی). چون MT5 کلاس دارایی نمی‌دهد، یک طبقه‌بند قطعیِ نام‌محور این کار را می‌کند؛ جفت‌های ۶حرفیِ فیات **قبل از** اسکن کریپتو بررسی می‌شوند تا `USDCAD` (زیررشتهٔ `USDC`) یا `CADAUD` (زیررشتهٔ `ADA`) کریپتو حساب نشوند — این دقیقاً همان اشکالی بود که تست E2E در بازبینی اول شکار کرد.
- هر گروه حداکثر ۴۰ ردیف رندر می‌کند؛ اضافهٔ گروه با «+N more…» جمع زده می‌شود. پاورقی «N symbols» تعداد دقیق کل نتایج است («1 symbol» مفرد). کوئری بی‌نتیجه: عبارت «No matching symbol» به‌جای خالی مطلق.
- جستجوی بی‌حساس به حروف (خواستهٔ راند ۳۵) دست‌نخورده است — کاربر با «Xau»، «xau» و «XAU» یکسان به XAUUSD می‌رسد.
- `src/renderer/css/app.css`: استایل `.sym-group-head` / `.sym-more` / `.sym-empty` / `#sym-count` (توکن‌های تم — هر دو تم دارک/لایت).

### 4) عرض پنجرهٔ تایم‌فریم — ۲۴۰px ← ۱۹۰px

- `#tf-menu.popup { width: 190px }`؛ چیدمان ردیف‌ها/گروه‌ها و flush-right بودن ستاره‌ها حفظ شد (تست D2: ستاره‌ها روی یک ستون، راست‌چین).
