## 1.6.0 — فاز 3 (سپتامبر 2026) — هسته Platform-Agnostic: آماده‌سازی برای وب و موبایل

> طبق نقشهٔ راه: لایهٔ مستقل از پلتفرم به درخت مستقل `src/core/` منتقل شد — **صفر ارجاع به host-global** (window/document/electronAPI/localStorage) که با تست اجباری می‌شود. صفر تغییر رفتاری؛ ۱۰۹ بررسی E2E سبز (راند ۲۵: ۳۰، راند ۲۶: ۱۲، راند ۲۷: ۱۱، راند ۲۸: ۱۰، فاز ۲: ۵، **فاز ۳: ۳۱ — جدید**) + بوت واقعی Electron 33 روی `file:` با `sandbox:true` بدون خطا. سند کامل: `docs/PHASE3-CORE.md`

### Added
- **`src/core/` (لایهٔ هسته):** `env.js` (تنها نقطهٔ مجاز لمس host globals: ENV + seam ذخیره‌سازی JSON)، `util.js` (helperهای خالص ریاضی/زمان/هندسه به‌صورت named export)، و انتقال `logger` / `errors` / `indicators` (۲۷ اندیکاتور) / `state` / `timezone` / `feed` به هستهٔ قابل‌اجرا در Node/مرورگر/Electron.
- **`src/platform/electron/loghost.js` (آداپتر میزبان):** transport فایل-لاگ IPC، crash net (error/unhandledrejection)، toast محدودشده و flush هنگام بستن — همهٔ کد وابسته به Electron رندرر در یک فایل جمع شد؛ پوستهٔ وب (فاز ۴) آداپتر هم‌قرارداد خودش را می‌سازد.
- **`Log.setTransport(fn)`:** تنها API جدید لاگر — sink خروجی تزریقی می‌شود؛ منطق batch (1.5s/60/400) در هسته ماند و اکنون در Node هم تست‌پذیر است. `stats().ipc` و رفتار headless دست‌نخورده.
- **`new Feed(url)`:** نشانی WebSocket تزریقی می‌شود (پیش‌فرض همان `ws://127.0.0.1:8777`) — برای شل وب و رلهٔ راه‌دور بدون تغییر هسته.
- **`tests/unit/test_phase3_core.py` (۳۱ بررسی جدید):** T1 اجرای واقعی همهٔ ماژول‌های هسته در Node خالص (بدون DOM): ring/scrub/transport/export، کاتالوگ خطا + register/raise/wrap، ریاضیات SMA/RSI، قیف timezone، کاتالوگ‌های state، تزریق URL فید؛ T2 ممیزی استاتیک خلوص (فقط `env.js` مجاز به host globals است) + resolveشدن همهٔ importها؛ T3 بوت مرورگر روی چیدمان جدید با صفر خطای کنسول.

### Changed
- **چیدمان منبع:** ۶ ماژول از `src/renderer/js/` به `src/core/` منتقل شد (۴۳ import در ۲۰ فایل به‌صورت مکانیکی بازنویسی و با ممیزی resolve تأیید شد)؛ نام exportها بدون تغییر.
- **`state`:** همهٔ persistence از `ENV.storage` می‌گذرد (در رندرر همان localStorage، در Node بدون اثر، در فاز ۴ قابل تعویض با Capacitor Preferences).
- **`src/renderer/js/core/util.js`:** حالا facade است — helperهای خالص از هسته re-export می‌شوند + helperهای DOM ($، el، toHex، fitPopup) — همهٔ ~۱۵۰ فراخوانی `U.x` بدون تغییر ماندند.
- **`app.js`:** اولین import = loghost (crash net قبل از ارزیابی هر ماژول دیگر فعال می‌شود — همان زمان‌بندی لاگر راند ۲۸).
- ابزارها: `check_esm.sh` اکنون ۳۳ ماژول (هسته + platform + رندرر) را چک می‌کند؛ `audit_imports.py` مسیرهای ROOT-relative را می‌فهمد؛ ROOT تست‌های http به `src/` تغییر کرد (مسیر صفحه: `/renderer/index.html`).
- نام متغیر محلی `window` در محاسبهٔ MFI به `win` تغییر کرد (خلوص استاتیک هسته — هیچ اثر رفتاری).

## 1.5.0 — فاز 2 (سپتامبر 2026) — ماژولارسازی ES Modules + JSDoc: پایهٔ معماری برای وب و موبایل

> طبق نقشهٔ راه تأییدشده: رندرر از ۲۸ اسکریپت IIFE با ~۲۹ گلوبال `window.*` به **گراف ماژول استاتیک ES** با یک نقطهٔ ورود تبدیل شد. صفر تغییر رفتاری؛ ۶۸/۶۸ بررسی E2E سبز (راند ۲۵: ۳۰، راند ۲۶: ۱۲، راند ۲۷: ۱۱، راند ۲۸: ۱۰، فاز ۲: ۵) + بوت واقعی Electron 33 روی `file:` با `sandbox:true` بدون خطا. سند کامل: `docs/PHASE2-ESMODULES.md`

### Added
- **نقطهٔ ورود واحد:** `index.html` فقط `<script type="module" src="js/app.js">` + اسکریپت کلاسیک vendor (LightweightCharts UMD قبل از گراف ماژول اجرا می‌شود)؛ ۲۸ تگ اسکریپت حذف شد.
- **`js/ui/rightpanel.js` (ماژول جدید):** کنترلر پنل راست از `app.js` استخراج شد (شکستن تمیز چرخهٔ app↔panels).
- **خروجی‌های جدید:** `priceDigits()` از `core/feed.js` (نقشهٔ digits فید زنده را می‌خواند؛ `util` برگِ بدون وابستگی ماند)، `Theme.th()` در `core/theme.js`، `recompute/tickRecompute/updateIndicatorRows` به‌صورت export نامی از `indicators-ui.js`.
- **اسکریپت‌های نگهداشت:** `scripts/check_esm.sh` (node --check روی ۳۰ ماژول)، `scripts/audit_imports.py` (ممیزی/ترمیم خودکار import ها با حذف کامنت/رشتهٔ آگاه از interpolation)، `tests/unit/test_phase2_modules.py` (گارد ماژولارسازی: اگر هر گلوبال تبدیل‌شده دوباره روی `window` ظاهر شود FAIL می‌شود).
- **JSDoc:** سربرگ `@module` برای هر ۳۰ ماژول + مستندسازی export های عمومی و توابع جابه‌جاشده.

### Changed
- **صفر گلوبال ماژولی روی `window`:** همهٔ ارجاعات بین‌فایلی حالا `import`/`export` نامی‌اند؛ گاردهای دفاعی `typeof X !== 'undefined'` حذف شدند (گراف قطعی است).
- **دسترسی تست/دیباگ از یک نما:** `window.__app` با ۲۶ کلید (App/Manager/Toolbar/UI/Indicators/IndicatorsUI/Log/AppErr/…) — همهٔ مجموعه‌های E2E به این نمای مجاز مهاجرت کردند.
- **قاعدهٔ چرخه‌ها:** چرخه‌های ماژول (manager↔toolbar↔ui↔settings↔theme و …) فقط با ارجاع runtime مجازند؛ دو مورد ارزیابی-زمان (اتصال hook اندیکاتورها و `getSnapshotPalette`) به الگوی «import + delegate» بازساخت شد تا از خطای TDZ جلوگیری شود.
- `harness.py` و ۵ سوت قدیمی‌تر (round 25/26 و bug suites) به مسیرهای نسبی و نمای `__app` مهاجرت پیدا کردند (قبلاً به مسیر مطلق قدیمی اشاره داشتند و از کار افتاده بودند).

### Security
- بدون تغییر — CSP سختگیرانهٔ راند ۲۸ با `script-src 'self' file:` ماژول‌های `file:` را پوشش می‌دهد؛ بوت واقعی Electron با `sandbox:true` + `contextIsolation` تأیید شد.

## 1.4.0 — راند 28 (سپتامبر 2026) — سه سیستم زیربنایی: لاگ و مانیتورینگ + خطای ساخت‌یافته + سخت‌سازی امنیتی

> شروع «نقشهٔ راه پایهٔ قوی»: طبق تصمیم کاربر، راند ۲۸ بدون دست‌زدن به معماری فعلی (IIFE، بدون build step)، سه سامانهٔ زیرساختی را روی همان ساختار نشاند تا دیباگ راحت و مسیر آیندهٔ وب/موبایل (Capacitor) هموار شود. ماژولارسازی ES Modules + JSDoc فاز بعدی است.

### Added — لاگ و مانیتورینگ (سیستم ۱)
- **لاگر مرکزی `core/logger.js` (`window.Log`):** ورودی ساخت‌یافته `{t, seq, lvl, cat, msg, ctx}` با ۴ سطح (debug/info/warn/error)، دسته‌بندی آزاد (app/provider/feed/chart/login/panel/selftest/security/error)، **Session ID** برای هر اجرا، **ring buffer ۳۰۰۰تایی** (فراتر → شمارش dropped)، شمارشگر سطح/دسته.
- **فایل لاگ سمت main (`main.js`):** JSONL در `userData/logs/app-YYYY-MM-DD.log` با **rotation خودکار در ~۲MB** + **هرس لاگ‌های بالای ۷ روز** در بوت؛ رویدادهای main (بوت، خروج provider، uncaughtException، بسته‌شدن app) هم در همان فایل با `proc:'main'` ثبت می‌شوند؛ renderer به‌صورت **دسته‌ای (batch ۱.۵ث / ۶۰تایی)** و خطاها فوری ارسال می‌کند.
- **پنل Diagnostics (تب جدیدِ ریل راست):** نمای زنده با فیلتر سطح (DBG/INFO/WARN/ERR)، فیلتر دسته (خودکار از stats)، جستجوی متنی، توقف/ادامهٔ نما، ردیف‌های قابل‌بازشدن (کلیک → ctx رنگی JSON)، کپ DOM در ۶۰۰ ردیف؛ **نوار stats** (شناسه نشست، uptime، تعداد ورودی‌ها، err/warn، وضعیت فایل‌سینک).
- **Export یک‌کلیکی:** دیالوگ ذخیرهٔ `mt5-diagnostics-<session>-<timestamp>.log` (متن خوانا) یا `.json` (ساخت‌یافته) — در حالت مرورگر (تست) fallback دانلود ساده.

### Added — خطای ساخت‌یافته (سیستم ۲)
- **`core/errors.js` (`window.AppErr`):** کلاس `AppError` با **کاتالوگ ۱۹ کد** (PROVIDER_*/FEED_*/BARS_*/INDICATOR_*/IPC_BAD_PAYLOAD/...) هر کدام با `severity`/`category`/`userMessage` (متن کاربرپسند)/`hint` (گام بعدی پیشنهادی).
- **کاتالوگ باز:** `AppErr.register(code, spec)` — لایه‌های آینده بدون دست‌زدن به این فایل کد خودشان را اضافه می‌کنند (قابلیت توسعه در هر لایه).
- **`AppErr.wrap()` idempotent** (چیز پرتاب‌شدهٔ دلخواه → AppError، خودِ AppError دست‌نخورده) و `AppErr.raise()` (ساخت + لاگ) — `manager.loadBars`، `login.connect` و feed حالا از این مسیر لاگ می‌کنند.
- **شکار سراسری (crash net):** `window.onerror` + `unhandledrejection` از لحظهٔ بوت در لاگر نصب شده‌اند؛ خطای غیرمنتظره → ورود error در لاگ + **toast نرخ‌محدودشده (۵ثانیه)** با ارجاع به پنل Diagnostics؛ سمت main هم `uncaughtException/unhandledRejection` به فایل لاگ می‌رود.

### Added — سخت‌سازی امنیتی (سیستم ۳)
- **CSP سختگیرانه** در `index.html` (round 28): بدون اسکریپت inline، بدون مبدأ ریموت؛ فقط `self/file:` + `ws://127.0.0.1:8777` برای فید.
- **Electron:** `sandbox: true` اضافه شد (در کنار `contextIsolation` و `nodeIntegration:false` موجود)؛ **`setWindowOpenHandler` → deny همه‌جا** + **`will-navigate` فقط file:** (رندرر هرگز به صفحهٔ ریموت نمی‌رود؛ هر تلاش → لاگ security).
- **اعتبارسنجی همهٔ پیام‌های IPC** در main: `start-provider` (شکل، طول‌ها، الگوی login، حذف کنترل‌کاراکترها)، `accounts-save` (سقف ۱۲ حساب + طول‌ها)، `log-batch` (سقف ۵۰۰ ورودی/۸KB ctx)، `notify` (طول عنوان/متن)، `logs-export`/`save-*` (سقف حجم و نام امن) — ردشدن → رویداد `[IPC_BAD_PAYLOAD]` در لاگ security.
- **حریم لاگ:** scrub خودکار context در لاگر (کلیدهای password/pass/token/secret/authorization/cookie → `•••redacted•••`، عمق≤۳، طول≤۵۰۰) + لاگ اتصال login **هرگز شامل password نیست** (سمت main هم فقط mode/login/server).
- `safeStorage` حساب‌های ذخیره‌شده (DPAPI) از قبل موجود بود — حفظ شد؛ پرووایدر هم از قبل فقط روی `127.0.0.1` گوش می‌دهد.

### Instrumented (هم‌رسانی بدون تغییر رفتار)
- `feed.js`: اتصال/قطع (transition-based بدون اسپم reconnect)، timeout هر درخواست، پیام غیر-JSON.

### Selftest (داخل پنل)

### Tests
